# 章構造の品質保証パイプライン

スキャン書籍を章別オーディオブックにする上で、**章構造の正しさ**が製品価値そのものになる。
本書は 67冊の実測に基づき、なぜ変換器（DN）単独では章構造を作れないのか、
どうやって LLM を**ハルシネーションなしで**噛ませるのか、その設計を記録する。

---

## 1. 測定: 何が壊れていたか

Sonnet 5 に全 67冊の章一覧を意味判定させた結果（`scripts/audit_audiobooks.py`）:

| 判定 | 冊数 |
|---|---|
| 健全 | 27 |
| **要対応** | **40** |

要対応 40冊の内訳（重複あり）:

| 壊れの型 | 冊数 | 症状 |
|---|---|---|
| `scrambled` | 35 | 第1章が最後に来る等、章の読み順が崩れている |
| `missing_title` | 25 | 「第3章」だけでタイトルが無い／途中で切れる |
| `fragment` | 7 | 章タイトルが本文の途中断片（「決心をしました。らうことこそが」等） |
| `duplicate` | 4 | 「第1部」と「第一部」が別章として重複 |

**正規表現ベースの監査では、この分類はできなかった**（長い実タイトルを誤検出し、
順序崩れを見逃す）。章構成の健全性判定は意味理解を要する、というのが第一の学び。

---

## 2. 原因: DN（変換器）の限界

DN（superbook-pdf）は**テキスト抽出は良好**だが、**構造の検出は信頼できない**。

| 層 | 評価 | 実測 |
|---|---|---|
| ラスタライズ + OCR(YomiToku) | 良好 | 320ページ本で本文17万字をクリーンに抽出 |
| **読み順** | 破綻 | 34/67冊で章順スクランブル。[#58](https://github.com/clearclown/Rust_DN_SuperBook_PDF_Converter/issues/58) 修正後も再現するため [#69](https://github.com/clearclown/Rust_DN_SuperBook_PDF_Converter/issues/69) で主経路の採番確認を依頼中。下流では**章番号による読み順の再構成**で回避する（下記 3-2） |
| **見出し検出** | 破綻 | 偽陽性（著者名・ページ番号・本文行を `##` 化）と偽陰性（`##` が 0個の本）が同時に起きる（[#61](https://github.com/clearclown/Rust_DN_SuperBook_PDF_Converter/issues/61)） |
| **本編/巻末の区別** | 無し | 出版目録・索引・他書の題名一覧を本文として取り込む（[#60](https://github.com/clearclown/Rust_DN_SuperBook_PDF_Converter/issues/60)） |
| Markdown 書式 | 問題（修正済） | ページ区切り `---` が下流で Setext 見出しと誤認され章検出が暴走（[#59](https://github.com/clearclown/Rust_DN_SuperBook_PDF_Converter/issues/59)） |

### `---` の Setext 爆発（#59）

CommonMark では「非空テキスト行の直後の `---`」は前行を `<h2>` にする。OCR 本文は
各ページ末に本文行＋`---` が来るため、**本文行が大量に見出しへ化ける**。

- 実測: 320ページ本で `---` が 320本、うち **286本が Setext H2 に化けた** → 章検出が暴走
- 対策（下流）: `gateway/src/chapters.rs` の `collect_headings` を **ATX 見出し限定**に
- 対策（上流）: DN 側で `---` を HTML コメントへ変更（修正版 `f6032ad` で確認済み: `---` 0本 / `<!--` 320本）

### 修正版 DN でも章構造は作れない

DN 修正版（`f6032ad`）で 320ページ本を再変換した結果:

| 修正 | 結果 |
|---|---|
| #59 `---` → HTMLコメント | ✅ 効いている |
| #61 見出し検出 | ❌ 不十分（manifest **722章**、`##` **738個**。節レベルの `●` `■` まで昇格） |
| #60 巻末検出 | ❌ `main_content_end_page: None` |

**結論: 章構造は下流（LLM）で復元するしかない。** 章マーカーの形式は本ごとに違い
（第N章 / エピソードN / 漢数字一〜十四 / [I][V] / 日記の日付…）、意味理解なしには
統一的に扱えない。

## 3. 設計: 決定論 + 抽出LLM + 標本Vision

ハルシネーションは**「生成」に宿り、「抽出・分類」にはほぼ宿らない**。この性質を使い、
LLM に文章を書かせず、**DN が抽出した文字列に印を付けさせる**だけにする。

```
① DN（決定論・安価・再現可能）
     OCR本文 ＋ ページ順 ＋ 書式
        ↓
② 抽出LLM（Sonnet 5・テキストのみ・1冊1回 ≒ 数円）
     「本物の章の開始位置」を **本文からの逐語アンカー**で返す（文章は書かない）
        ↓ 決定論ガード（下記）
③ 標本 Vision QA（怪しい所だけ・照合役）
        ↓
④ Sonnet 監視（最終ヘルスチェック）
```

### ハルシネーションが入らない理由（設計保証）

| 懸念 | 対策 | 実装 |
|---|---|---|
| LLM が存在しない位置に章を作る | **アンカー逐語一致必須**。一致しなければ棄却 | `_find_anchor` |
| LLM が章タイトルを創作する | **タイトルの中身が本文に実在必須**。未実在はマーカーのみに縮退 | `title_is_grounded` |
| 章が欠落・偏る | **カバレッジの決定論チェック**（前付け過大・分割漏れ・空章） | `coverage_warnings` |
| Vision の画像OCR幻覚 | Vision は**転写に使わない**。「章見出しの有無」を報告する照合役のみ | `qa_sample_vision.py` |

### 3-2. 読み順の再構成（順序崩れ対策）

変換器のページ順バグ（[#69](https://github.com/clearclown/Rust_DN_SuperBook_PDF_Converter/issues/69)）で、
ソースの時点で章が前後している本が **34/67冊**ある。見出しを注入するだけでは直らないため、
`build_injected_source` が次の手順で読み順を復元する:

1. 各章のアンカーを**独立に**探す（従来は前章より後ろしか探さず、順序が崩れた本で
   後続章が軒並み棄却されていた）
2. 物理順にセグメント化（各章 = 自分のアンカーから次のアンカー直前まで）
3. **章番号順に並べ替える**（前付け → 本編（番号順）→ 後付け）
4. 連結し、**本文長が一致することを検証**（欠落したら警告）

**安全側の判断**: 本編章の **60%以上から章番号が取れるときだけ**並べ替える。
番号が取れない本（コラム・戦略ノート等が主体）で無理に並べ替えると、改善ではなく
破壊になるため、そのときは物理順のまま残して理由を出力する。

### コスト構造

| 手段 | 単価 | 備考 |
|---|---|---|
| Vision で全ページ転写 | 約 $0.02/ページ（320p 本で ≒ $6.5/冊） | 採用しない |
| **抽出LLM（本方式）** | **1冊 1回 ≒ 数円** | 100倍以上安い |
| 標本 Vision QA | 数ページ/冊 | 怪しい所に集中 |
| TTS（音声化） | 最大のコスト源 | 品質ゲートが未達章を **TTS前に棄却**（無駄な音声化を防ぐ） |

## 4. ツール

| スクリプト | 役割 |
|---|---|
| `scripts/audit_audiobooks.py` | **Sonnet 監視**。各本の章構成を意味判定し `healthy`/`broken` と壊れの型を返す。`--json` で対象一覧、`--name` で1冊 |
| `scripts/llm_chapter_detect.py` | **抽出LLM章検出**。本物の章一覧＋開始アンカー＋巻末終端を取り、ノイズ見出しを平文化してから `##` を注入。決定論ガード込み。`--apply` なしは dry-run |
| `scripts/qa_sample_vision.py` | **標本 Vision QA**。ランダム標本＋章境界ページを Vision で照合し、見落とし章/偽章/巻末残りを検出（seed 固定で再現可能） |
| `scripts/inject_chapter_headings.py` | 正規表現版の章注入（本文中の反復する柱から検出）。標準的な和書で有効、翻訳書等は LLM 版を使う |
| `scripts/orchestration/ensure_worker.py` | 3台（studio/mini/asus）の **DN バージョン整合**と準備確認。古ければ更新＋再ビルド |

### 運用ループ

```
audit_audiobooks.py --json     # 壊れている本を特定（TTSを使わない・安い）
  → llm_chapter_detect.py --apply   # source に正しい章見出しを注入
  → 再生成（gateway /audiobooks/generate）
  → qa_sample_vision.py          # 標本Visionで抜き取り検査
  → audit_audiobooks.py          # 再監視。healthy になるまで
```

**重要**: 盲目的に全冊を再生成しない。監視で対象を絞ってから再生成することで、
最大コストである TTS の無駄撃ちを避ける。

## 5. 生成側の堅牢化（`sidecar/podcast_runner.py`）

章構造とは別に、生成そのものが落ちる問題も実測から潰した。

| 問題 | 実測 | 対策 |
|---|---|---|
| 台本LLMが JSON キーを壊す | `"dialogue"` が `"dialogே"` / `"dialogine"` / `"dialogume"` に化け、章がまるごと失敗 | パース前に dict レベルで**キーを自動修復**＋最大5回リトライ |
| Gemini TTS が `parts` 無し応答 | esperanto が `KeyError('parts')` で章全体を落とす（再生成バッチで多発） | `agenerate_speech` をリトライ付きに差し替え |
| 薄い章の水増し | 中扉・はじめに等を固定3部構成に強制 → LLM が捏造して長さ比 12.38 / grounding 0.19 → ゲート棄却 | **内容量に比例**した簡潔な台本にし、ゲートも薄章は grounding 中心で判定（長さ比 12.38 → 2.59） |

### 品質の実測（ハルシネーション）

修正後のパイプラインで生成した1冊（9章）の実測:

- grounding（台本の固有名詞・数値のうち本文に実在する割合）: 実章 **0.72〜0.91**
- **数値を含む捏造（架空の金額・件数など）: 全9章で 1件のみ**
- 長さ比: 全章 1未満（0.13〜0.53）＝本文より短く要約しており、水増ししていない

「未実在」と判定される語の大半は師匠ペルソナの話し言葉（「コンセプト」「土台」等）で、
事実の捏造ではない。**指標の絶対値ではなく、数値・固有名詞の捏造有無で評価すべき**。

## 6. 分散処理（3台）

| 台 | 演算 | 役割 |
|---|---|---|
| studio | MPS | ハブ（DB/API/gateway/sidecar）＋変換 |
| mac-mini | MPS | 変換（OCR） |
| ASUS ROG X13 | CUDA (RTX 3050 Ti, VRAM 4GB) | 変換（OCR）。VRAM が小さいので OCR バッチは小さめ |

**鉄則: 使う前に DN のバージョンを確認し、古ければ更新する。** 時代遅れのバイナリで
変換すると、修正済みのバグを再び踏む。`ensure_worker.py` がこれを自動化し、
使用した DN コミットを来歴として返す（ジョブに記録できる）。
