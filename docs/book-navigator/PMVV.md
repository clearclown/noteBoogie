# noteBoogieの役割と成功条件

更新日: 2026-10-03。方針の決定は[PDR-003](../7-DEVELOPMENT/decisions/PDR-003-personal-library-and-mangaga.md)に記録する。本書はnoteBoogie固有の方針であり、フォーク元Open Notebookの[VISION.md](../../VISION.md)と区別する。以下は開発の到達目標で、実装済み機能の一覧ではない。

## Purpose 本を日常の読書と学びに使えるようにする

一度取り込んだ本を、生活の中で繰り返し読み、理解し、必要なときに参照できるようにする。

本を持っていても、読む時間が取れない、疑問が残る、読んだ内容を必要な場面で取り出せないことがある。原本への参照を保ち、読む・聴く・質問する体験と自分の記録をつなげることで、この負担を減らす。

## Mission 蔵書と読書記録を管理する

**noteBoogieは、蔵書の原本・本文・出典・読書記録を管理し、読む・聴く・質問するための情報を整える、個人用の蔵書基盤である。**

| 担当 | 役割 |
|---|---|
| noteBoogie | 原本・本ID・版を保存し、OCR、本文構造、検索、出典付き回答、要約、音声を管理する。読書記録を受け取り、Webで確認・修正・参照できるようにする |
| mangaga | iPhoneの日常利用を担う。本棚、原本表示、RSVP、音声、質問、オフライン保存、読書中の記録を扱う |
| mangaga側の配信用アダプター | 一つの認証入口で本と記録を受け渡す。既存Rust APIによる暗号化と配信を担う |

モデルと外部送信方針はnoteBoogieに集約する。mangagaに別のAI設定基盤を作らない。音声化は、読む時間を補う手段として位置づける。

## Vision 読書を続けられ、学んだことを取り出せる

最初の完成条件は、一冊を取り込んでmangagaへ持ち出し、PCが停止していても読めること、読書記録をPCへ戻せること、再処理してもその記録を失わないことである。

次の完成条件は、通勤中に章を聴き、疑問を質問し、原本で確かめて続きを聴けること。その質問・回答・自分のメモを後日の仕事や学習で参照できる状態を目指す。新しいAI処理にはPCへの接続が必要であり、オフラインでは取得済みデータの利用と記録・質問の下書きまでを支える。

| 確かめたい成果 | 記録するもの |
|---|---|
| 本を日常へ持ち出せる | 初回設定と本ごとの作業を分け、操作数、手作業時間、処理・取得時間を測る |
| 読書の続きを失わない | PC停止、通信断、端末再起動、版更新の後に再開できたかを確認する |
| 疑問を解ける | 回答の根拠へ戻れるか、疑問が解けたかを利用者が確かめる。引用一致だけで理解や正しさを認定しない |
| 学んだことを使える | 過去の質問・メモを見つけ、判断や提案で参照した具体例を残す |
| 維持する負担が小さい | 修正時間、失敗からの復旧時間、費用、保存容量を本ごとに測る |

時間・費用の受入値は、代表的な本と実行環境で測定して決める。未測定の値を達成済みの指標にしない。詳細は[受入計画](MANGAGA_ACCEPTANCE.md)に定める。

## Values 原本と自分の記録を守る

判断に迷ったときは、次の順で優先する。

| 順位 | 価値 | 要件への反映 |
|---|---|---|
| 1 | 原本と出典を確かめられる | 原本のバイト列とOCR原文を保つ。修正本文、AIの説明、利用者の考えを区別し、出典を捏造しない |
| 2 | 読書と記録が続く | 部分失敗でも読める完成版を残す。位置・注釈・質問履歴を、同期競合や再処理で失わない |
| 3 | 自分で管理できる | 保存場所、送信先、費用、削除、書き出しを利用者が選ぶ。連携経路では未設定の外部AIへ自動送信しない |
| 4 | 内容を理解しやすい | 本文と注記を適切に表示する。音声解説では要点を落とさず、耳で分かる構成にする |
| 5 | 手間を増やさない | 本ごとの手動変換・転送を減らし、失敗箇所と復旧方法を示す |

本の説明には出典を求める。応用の提案を生成する場合はAIの解釈と表示し、本に書かれている主張と混同させない。以前の台本評価の重みは音声品質を測る既存の実装指標であり、上記の製品全体の成功指標を代替しない。

## 初回はPDFの読書と記録の往復を完成させる

対象は一人の所有者の書庫とする。初回の取り込み対象は文字付きPDFと画像PDFで、縦書き日本語・横書き日英混在を含む。読書用本文を準備できない本は原本のみ利用可とし、RSVP対応済みと表示しない。EPUBの直接取り込みは後続とし、mangagaにある既存のEPUB機能とは区別する。

| 段階 | 到達点 |
|---|---|
| A 契約 | 本・版・出典・成果物・記録の仕様と共通テストデータを両側で検証する |
| B 読書 | 一冊を取り込み、確認して公開し、iPhoneで取得後にオフラインで読める |
| C 記録 | 位置・しおり・注釈を往復し、競合・本文修正後も残せる。BとCを初回の完成範囲とする |
| D 質問と音声 | 聴く・質問する・原本で確かめる・再開する・後日参照する流れを通す |

段階Dでは章への質問、章音声、回答履歴を必須とする。音声での質問入力、端末上だけで動くAI、単語単位の音声と本文の同期、要約専用画面は後続の検討対象とする。既存のメンター機能やWebの音声機能は再利用し、mangagaへの連携完了と混同しない。

SaaS化、多利用者、課金サービス、汎用文書編集は今回の範囲に含めない。フォルダ監視と分散処理は、既存Web取り込みでB・Cを通した後の運用改善とする。Webの画面構成は本文確認と管理の仕事から設計し、従来の3ペイン集約を固定要件にしない。
