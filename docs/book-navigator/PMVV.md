# Book Navigator — PMVV と逆算した要件

このプロジェクトが何のために存在し、何をもって「できている」と言えるのかを定義する。
機能追加・品質基準・優先順位はすべてここから逆算する。上流 Open Notebook の
[VISION.md](../../VISION.md) はフォーク元の指針であり、本書は**このフォーク固有の目的**を扱う。

---

## Purpose（存在意義）

**手元の紙の本を、耳で聴いて頭に入る形に変える。**

積んである専門書・実用書は、読む時間が取れないまま価値を失っていく。一方、通勤・
移動・家事の時間は耳が空いている。この2つを繋ぐのが本プロジェクトの存在意義。

## Mission（使命）

**スキャンした蔵書を、章ごとの「信頼できる語り」と「質問できる知識」に変換する。**

- 変換の対象は**自分が所有する本**（スキャンPDF、縦書き和書を含む）
- 出力は**章単位のオーディオブック**と、**出典付きで質問できるナレッジベース**
- 語り手は**師匠（メンター）**。単なる要約読み上げではなく、蔵書を踏まえて相談に乗る

## Vision（成功した状態）

**自分が毎日それを使い、聴いた内容を信頼して仕事の判断に使える。**

成功の判定は「機能が実装されたか」ではなく「**自分が使い続けているか**」。
使われない機能は、正しく動いていても価値がない。

## Value（判断基準）

意思決定で迷ったとき、この順で優先する。

| 順位 | 価値 | 意味 |
|---|---|---|
| 1 | **本に書いてあることだけを言う** | 捏造は最悪の欠陥。聴いた内容を信頼できないなら、このプロジェクト全体が無意味になる |
| 2 | **要点を落とさない** | 忠実であっても、章の主題に触れていなければ聴く価値がない |
| 3 | **耳で分かる** | 構成が明快で、語りとして自然であること |
| 4 | **自分の管理下に置く** | 蔵書データは外に出さない。著作物はリポジトリにも push しない |
| 5 | **止まらない** | 一部が失敗しても全体は前に進む（リトライ・監視・部分復旧） |

### 位置づけ（2026-08 決定）

**自分の蔵書のための実用ツール**として完成させる。SaaS 化・多利用者は後継プロジェクト
（bookcast）に委ね、ここでは**品質と使い勝手**に集中する。したがって
「多くの人に使えるか」ではなく「**自分が毎日使えるか**」で判断する。

---

## 逆算: Vision から要件へ

「毎日使い、聴いた内容を信頼できる」ためには何が真でなければならないか。

### A. 聴いた内容が信頼できる（Value 1・2 の帰結）

| 必要な状態 | 測り方 | 現状 |
|---|---|---|
| 台本が本に無いことを言わない | `grounding` ≥ 0.8 | 実測 0.72〜0.91、数値の捏造は9章で1件 |
| 章の要点を落とさない | **`coverage` ≥ 0.8**（本文の主題語のうち台本が触れた割合） | **指標を新設**（従来は測っていなかった） |
| 水増ししない | `length_ratio` が許容帯 | 薄章対応で 12.38 → 2.59 に改善 |
| 未達の台本を世に出さない | 品質ゲートが TTS 前に棄却 | 実装済み。棄却11章は TTS を消費していない |

**合成報酬の重みは、この優先順位そのもの**（`scripts/eval_transcript.py`）:

```
grounding 0.40  >  coverage 0.30  >  structure 0.15 + politeness 0.10  >  length 0.05
   忠実性            網羅性               聴きやすさ                      補助
```

### B. 章の区切りが正しい（聴く体験の前提）

章がずれていれば、内容が正しくても聴けない。変換器（DN）は本文抽出は良好だが
構造検出は信頼できないため、下流で復元する。詳細は
[QUALITY_PIPELINE.md](QUALITY_PIPELINE.md)。

| 必要な状態 | 測り方 | 現状 |
|---|---|---|
| 章が本の実構造と一致 | Sonnet 監視が `healthy` | 67冊中 27健全 → 16冊修復済み、残り約24冊 |
| 見落とし章・巻末混入がない | 標本 Vision QA が `ok` | 実装済み・実証済み |

### C. 毎日使える（Vision の帰結）

| 必要な状態 | 現状 |
|---|---|
| 聴きたい章にすぐ辿り着ける | 章名が正しく表示される（二重表記を解消済み） |
| 再生できる | 遅延ロード化で復旧（全件 eager fetch が原因で再生不能だった） |
| 持ち出せる | 章ZIP一括DL・`make export-audiobook` |
| 迷わない UI | NotebookLM 型の3ペイン集約は**未着手**（リブランド・導線整理まで完了） |

### D. 蔵書を守る（Value 4）

| 必要な状態 | 現状 |
|---|---|
| 書籍データを公開しない | `data/` `surreal_data/` `input/` を gitignore。コード・テスト・docs からも実書名と本文断片を除去済み |
| データが壊れない | DB・音声をホスト側 bind mount に置く設計。VM 消失時もデータは無傷だった |

## 現在地と優先順位

Vision（毎日使える・信頼できる）に対して、埋まっていないのは次の3つ。

| 優先 | 課題 | 根拠（どの Value から来るか） |
|---|---|---|
| **1** | **未修復の約24冊の章構造** | Value 1・2。章がずれた本は聴けない＝Vision に直結 |
| **2** | **UI の3ペイン集約（NotebookLM 型）** | Vision「毎日使う」。機能はあるが導線が分散している |
| 3 | 3台分散の完成（Stage 2 ディスパッチャ） | Value 5。処理時間の短縮＝運用の楽さ |

**やらないこと**: 多利用者対応・課金・クラウド運用（bookcast に委ねる）。
「あれば便利」でも Vision から逆算して効かない機能は入れない。
