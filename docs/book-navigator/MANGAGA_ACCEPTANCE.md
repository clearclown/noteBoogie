# mangaga連携の完成条件と受入計画

更新日: 2026-10-03。本書は[PMVV](PMVV.md)と[提供側要件NB-01〜10](MANGAGA_INTEGRATION.md)の受入計画である。以下の試験は未実施であり、合格した一覧ではない。共通契約 **NBMG-20261003 / v0.1** のA〜Dを維持し、[契約補足](MANGAGA_CONTRACT_ADDENDUM.md)の採用を前提条件として管理する。

## 初回はPDFを持ち出して記録を戻せる

初回の完成範囲はB・C。既存Web取り込みから一冊の本を読み、記録を戻すまでを通す。フォルダ監視や分散処理を、この完成の前提にしない。

| 入力・内容 | 初回の扱い | できない場合の表示 |
|---|---|---|
| 文字付きPDF | 文字抽出と構造化。縦書き日本語、横書き日英混在、段組みを検証 | 不確かなページは確認待ち。原本表示は維持 |
| 画像PDF | OCRと構造化。同じ読書用契約へ変換 | OCR不可・未完了を明示し、原本のみ利用可 |
| 文字と画像が混在するPDF | ページごとに経路を選ぶ。文字の重複抽出を防ぐ | 未処理ページと空白ページを区別 |
| ルビ・脚注・柱・ページ番号 | 役割を分け、ルビ/脚注は本文との対応を保持 | 対応不明を本文へ推測挿入しない |
| 図・表・数式 | 領域と原本への参照を残す。安全に読める本文だけをRSVPへ渡す | 平文化が不確かなら原本を開く。本文から消えているように見せない |
| EPUB・その他の形式 | noteBoogieへの新規取り込みは後続 | 取り込み前に未対応と表示。mangagaの既存対応とは区別 |
| 破損・解読できない暗号化PDF | 検証で停止し、原因を表示 | 読める原本・処理成功と表示しない |

原本・補助本文の実効サイズ上限は経路の最小値をcapabilitiesで返す。v0.1の調査値はnoteBoogie原本100 MiB、mangaga原本128 MiB、補助本文16 MiB。実装時に設定値と実際の検証を照合し、上限変更には転送・メモリ試験を伴わせる。

## AからDを順に検証する

| 段階 | 必須の受入シナリオ | 対応要件 |
|---|---|---|
| A 契約 | 本・版・位置・manifest・記録・エラーを同じfixtureでPython/Rust/Swiftが検証する。未知版や誤った所属を拒否する | NB-01/02/05/08、契約補足C-01/02/04/05 |
| B 読書 | WebでPDF追加→原本と本文を確認→版を公開→mangagaで一冊取得→PC停止・機内モード・アプリ再起動後も原本とRSVPを開く | NB-01〜05/08/10 |
| C 記録 | iPhoneのオフライン注釈→再接続→Web反映→Web編集→iPhone反映。再OCR後も旧版の位置と記録を失わない | NB-03/07/08/10、契約補足C-05 |
| D 質問と音声 | 章音声を取得→聴く→停止して質問→引用から原本へ移動→同じ音声位置から再開→後日Webで回答・メモを検索し書き出す | NB-06/07/09/10、契約補足C-03 |

段階Dのために、質問・引用・履歴のAPIとfixtureを追加する。新しい質問は接続中にPCで処理する。切断時には下書きを保ち、利用者の送信操作まで待つ。未取得の音声や回答をオフライン利用可と表示しない。

## 読書版の公開を判定する

| 検査結果 | 公開の扱い |
|---|---|
| 成果物欠落、ハッシュ不一致、ブロックIDの欠落・重複、未知ID、版の混在 | 本文付きパッケージを公開しない。取得済みの旧版は維持 |
| ページ/段落の欠落、重大な列順・章境界の疑いを検出 | 修正・再検査または原本との人による照合で解消するまで本文確認待ち |
| 表・数式の平文化が不確かだが、原本の該当領域へ戻れる | 制限を表示し、対応領域を飛ばしたことが分かる形で公開可 |
| 機械検査を通過し、未解消の停止条件がない | 機械検査済みとして公開可。人が全文確認済みとは表示しない |
| 利用者が原本と照合した | 確認したページ/ブロック、日時、検査版を保存。未確認部分はそのまま区別 |

公開判定器のスコア閾値は評価データで較正し、検査器と一緒に版管理する。共通要件の数値案は、正しい読書版を作れるかを評価する受入試験の指標であり、個々の本を自動で正しいと証明するものではない。

## 実書籍の品質と合成データの整合性を分けて測る

合成fixtureでは、意図しない原文の書き換えとブロックIDの欠落・重複を0件とする。再OCR・人による修正は別版として検証する。

実書籍は権利上利用可能な縦書き日本語4冊、横書き日英混在4冊、各30ページ以上を原本照合する。標本には本文だけでなく、段組み、ルビ、脚注、図表、章境界を含める。共通要件v0.1の提案値を引き継ぐ。

| 測定項目 | 受入値案 |
|---|---|
| ページ/段落の丸ごと欠落、重大な列順誤り | 評価標本で0件 |
| 正しいOCR原文に対する本文保持率 | 99.5%以上 |
| 正解ラベルを付けた柱・ページ番号の除去率 | 95%以上 |

これらは未実測の受入値案である。OCRの文字認識、本文の分類、語区切りを別に測り、図・表・数式も失敗例を記録する。試験対象と正解データを固定してから判定し、誤字だらけのOCRをそのまま保っただけで高品質としない。

質問には原文から答えられる例、答えられない例、似た語が別章にある例、誤った版、図のAI説明を根拠にしようとする例を用意する。引用の実在、範囲の遵守、回答を引用が支えるかを別々に評価する。検証前に回答品質の達成値を記載しない。

## 障害と再処理でも完成版と記録を守る

| 場面 | 必須の確認 |
|---|---|
| 同一原本の再投入、改名、同名別書籍、差し替え | 意図した本ID・原本版・読書版になる。既存の本を名前で上書きしない |
| worker/PC停止、変換器不在、モデル未設定、鍵待ち | 原因を区別し、永続状態から復旧する。受付だけで完成としない |
| 通知/記録の重複、適用後の応答喪失 | 二重登録や有料処理の重複起動を起こさない |
| 配信中断、アプリ終了、容量不足、不正ハッシュ | 新版を途中まで取得しても旧完成版を読める |
| 本文修正、音声のみ再生成、索引再構築 | 古い生成物の入力版を表示し、新しい本文と混在させない。質問履歴は当時の引用を保つ |
| 同時編集、時計のずれ、削除と未送信記録の競合 | 記録を無条件で上書き・復活・消去しない |
| 旧カーソル、長期オフライン、バックアップ復元 | 未送信記録を退避して再同期。本・版・鍵・引用の対応を復元する |
| 未認証、失効端末、別書庫、不正パス | 拒否する。ログに本文・鍵・認証情報が混入しない |
| 予算上限、費用不明、取消、容量上限 | 次の有料工程/生成を止め、完了済み成果物と記録を維持する |

## 通勤利用は実機でロックと再開を確かめる

画面ロックとVaultの手動ロックを区別する。Vaultの手動ロックとプロフィール変更では再生を停止し、本文・回答・復号状態を閉じる。ロック後に届く回答や取得結果で画面を再表示しない。

背景再生は、現在の背景移行時ロックとの両立を設計してから有効にする。利用者の再生許可、保持する鍵/復号データの範囲、解除条件をmangaga側で定め、画面消灯・アプリ背景移行・音声割り込み・イヤホン切断・再接続を実機で検証する。前景だけで再生できても、通勤利用の段階Dを完了としない。

質問を開いてから回答中に本・章を切り替える場合、元の質問範囲と再開先を保つ。対象音声が再生成された場合は、別音声へ同じ秒数を自動適用しない。PCが使えない場合は、取得済み音声の再生と質問の下書きを維持する。

## 運用の受入値を実測して決める

初回セットアップ、通常の一冊、修正が必要な一冊を分けて測る。APIやDBの内部名を利用者の操作手順に出さず、変換・転送の手作業を毎回要求しない。

| 測るもの | 測定方法 |
|---|---|
| 手作業の負担 | 取り込み、確認・修正、持ち出し、復旧の操作数と実作業時間 |
| 待ち時間 | ページ数・ファイル容量・端末・モデルを添え、処理/取得/質問応答の時間と失敗率を記録 |
| 費用 | 本/工程ごとの見積もり、実績または取得不能、予算上限で止まった箇所 |
| 保存容量 | 原本、旧版、生成物、記録、端末コピーを区別して測定 |
| 学びへの貢献 | 疑問が解けた場面、後日記録を見つけて判断・提案に使った場面と、見つからなかった例 |

操作数・時間・費用・保存量の許容値は代表書庫で測って受入前に固定する。数値のないまま「速い」「安い」「使いやすい」を合格理由にしない。既存の台本評価スコアと読了数だけで、理解や仕事への貢献を判断しない。
