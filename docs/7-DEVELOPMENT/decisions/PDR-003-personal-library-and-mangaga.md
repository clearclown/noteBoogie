# PDR-003: noteBoogieを蔵書基盤とし、mangagaを日常の読書画面にする

- **Status**: Accepted
- **Date**: 2026-10-03
- **Related**: [PMVV](../../book-navigator/PMVV.md), [連携要件](../../book-navigator/MANGAGA_INTEGRATION.md), [PDR-001](PDR-001-single-user-first.md)

## Context

従来の中心は本の音声化だった。mangagaとの連携では、同じ本をiPhoneで読んだり聴いたりしながら、質問と記録をPCへ戻し、原本の該当箇所を後から確かめられる必要がある。2026-10-03、利用者はこの役割分担と不足要件を反映した要件書の再構成を依頼した。

## Decision

日常の読書はmangagaが担う。noteBoogieは原本・本文・出典・版・読書記録とAI処理を管理し、Webから取り込み・確認・修正・参照を行えるようにする。配信用アダプターに認証・暗号化・受け渡しを集約する。

一人の所有者の書庫を対象とし、初回はPDFの読書と記録の往復を完成させる。次段階で章音声・質問・回答履歴をつなぐ。成功は読書の継続と知識の再利用、手作業・費用・容量の負担で判断する。原本、本の説明、AIの解釈、利用者の考えを区別する。

本決定はnoteBoogie固有の製品方針である。共通契約v0.1への追加項目は提案として分離し、両側の契約・Schema・fixtureが揃うまで確定した通信仕様と扱わない。

## Alternatives considered

- 音声化を引き続き中心に置く案: 原本を読む体験と読書記録の往復を、成功条件に含めにくい。
- noteBoogieのWebへ日常利用をすべて集約する案: mangagaの持ち出し・読書機能と役割が重なる。

## Consequences

本ID・版・出典・記録を、追加UIより先に整備する。3ペイン集約、フォルダ監視、分散処理は初回完成の前提から外す。既存の音声・質問・メンター機能を再利用し、移行で既存データを失わない。受入結果は要件と別に記録し、契約試験、実モデルの品質、実機の運用を区別する。
